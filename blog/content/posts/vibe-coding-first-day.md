## 시작은 한 줄이었다

> Next.js 15 + TypeScript + Tailwind로 시작해줘. 마크다운 파일로 포스트를 관리하는 구조로.

요청은 이게 전부였다. 폴더 구조를 어떻게 잡을지, 어떤 라이브러리를 쓸지는 정하지 않고 결과물부터 받아 보기로 했다.

## AI가 한 일

몇 분 뒤 돌아온 결과는 생각보다 완성도가 높았다.

- `create-next-app`으로 프로젝트 뼈대 생성
- `content/posts/*.md`를 읽어 목록·상세 페이지를 만드는 구조
- 코드 하이라이팅(Shiki), 태그 페이지, RSS, sitemap
- `draft: true`인 글은 production 빌드에서 제외

특히 **내가 말하지 않은 것까지 판단한 부분**이 인상적이었다. 레포 루트에 예전 Rails 프로젝트 파일이 남아 있었는데, 그걸 덮어쓰지 않고 `blog/` 폴더를 따로 만들었다. 이유도 같이 설명해 줬다.

## 막혔던 순간

순조롭기만 하지는 않았다. 첫 빌드가 CSS 최적화 단계에서 실패했다.

```text
TypeError: Cannot read properties of undefined (reading '0')
    at Parser.attribute (.../cssnano-simple/index.js)
```

원인은 `[data-theme*=" "]`처럼 값에 공백이 들어간 CSS 셀렉터를 Next.js에 내장된 cssnano가 처리하지 못한 것이었다. AI는 에러 로그를 보고 셀렉터를 바꿔 다시 빌드했고, 이 함정을 나중에 잊지 않도록 `CLAUDE.md`에도 적어 두었다.

## 배운 것

| 기대 | 실제 |
| --- | --- |
| 코드를 안 봐도 된다 | 결과를 **검증하는 눈**은 여전히 필요하다 |
| 한 번에 완성된다 | 에러 → 수정 → 재빌드 루프는 그대로다. 속도가 빨라졌을 뿐 |
| 프롬프트가 길어야 한다 | 짧게 시작하고 결과를 보며 좁혀 가는 편이 효율적이었다 |

가장 큰 변화는 **내 역할이 "작성자"에서 "리뷰어"로 바뀌었다**는 점이다. 무엇을 만들지 정하고, 결과가 맞는지 판단하고, 기록으로 남기는 일은 여전히 내 몫이었다.
